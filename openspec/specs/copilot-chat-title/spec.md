## Requirements
### Requirement: Title generation endpoint exists

The copilot backend SHALL implement `POST /api/generate-chat-title` accepting a JSON body with a `message` field and responding with JSON `{"title": string}`, matching the contract Sim's `requestChatTitle` already expects.

#### Scenario: Valid request with message
- **WHEN** Sim POSTs to `/api/generate-chat-title` with a non-empty `message`
- **THEN** the copilot SHALL respond 200 with `{"title": "<non-empty string>"}`

#### Scenario: Missing message
- **WHEN** the request body has no `message` or it is empty
- **THEN** the copilot SHALL respond with HTTP 400

#### Scenario: Unknown fields in request
- **WHEN** the request body includes extra fields (`model`, `provider`, `workspaceId`, `userId`)
- **THEN** the copilot SHALL accept the request and ignore the extra fields

### Requirement: Title is generated by the LLM using the default model

The copilot SHALL generate the title from the first user message using the configured LLM provider with `COPILOT_DEFAULT_MODEL`, and SHALL NOT use the request's `model` field (a Sim-side model name that may be invalid for the backend's single provider).

#### Scenario: Default model generates title
- **WHEN** the copilot generates a title and `COPILOT_DEFAULT_MODEL` is set
- **THEN** the copilot SHALL call the LLM with `COPILOT_DEFAULT_MODEL` and no tools, and return the generated title

#### Scenario: Request model ignored
- **WHEN** the request body includes a `model` different from the default
- **THEN** the copilot SHALL generate the title with the default model, not the requested one

### Requirement: Title output is sanitized

The copilot SHALL trim whitespace, strip surrounding quotes, and cap the returned title at approximately 60 characters.

#### Scenario: Title with surrounding quotes
- **WHEN** the LLM returns a title wrapped in quotes
- **THEN** the copilot SHALL strip the quotes before responding

#### Scenario: Overlong title
- **WHEN** the generated title exceeds 60 characters
- **THEN** the copilot SHALL truncate it to fit the cap

### Requirement: LLM failure falls back to a truncated message

When the LLM call fails (provider error, timeout, empty output), the copilot SHALL respond 200 with the first message truncated to the title cap, so the chat always receives a non-empty persisted title.

#### Scenario: Provider error during title generation
- **WHEN** the LLM call for the title errors
- **THEN** the copilot SHALL respond 200 with a title derived from truncating the request `message`

#### Scenario: Empty LLM output
- **WHEN** the LLM produces no text
- **THEN** the copilot SHALL respond 200 with a title derived from truncating the request `message`
